# Microsoft Code Reference

## Core Principles
- Prefer current official Microsoft reference documentation for Microsoft APIs.
- Verify exact type/member names and supported target frameworks when uncertain.
- Verify package ownership and versions before adding PackageReference entries.
- Do not invent APIs, overloads, configuration methods, or package names.
- Distinguish stable APIs from preview features.

When current documentation access is available, use it rather than relying on memory for version-sensitive APIs.
